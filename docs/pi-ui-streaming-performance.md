# Pi 终端 UI 提示与流式工具历史

## 提示来源

“此扩展使用了终端专用组件”原先由宿主 `pi/extension-ui.mjs` 的统一降级逻辑发出，并非模型生成。当前启用的 `@ff-labs/pi-fff` 在 `session_start` 注册 `ctx.ui.addAutocompleteProvider()`，会触发这条提示。当前安装的 pi-lens 根据 `ctx.mode` 在 RPC 模式跳过 TUI widget，不走该挂载路径。

Pi 1.2.0 SDK 自带 RPC 模式对自动补全、页眉、页脚等可选 TUI 工厂采用空操作。宿主现按相同行为跳过，保留按方法、调用来源去重的服务端诊断，不再发送聊天通知。文字 widget、状态、选择/确认/输入/编辑对话框及真正的扩展通知继续工作。前端也忽略旧宿主发来的同一条兼容提示，避免它成为助手消息或覆盖运行状态。

## 流式卡顿

历史工具卡片原先在每次文本刷新时重新读取结果、清理终端控制字符、拆分所有输出行并构建正文 JSX。即使工具记录已经完成且折叠，仍会执行；大工具历史会不断占用界面线程。

`PiToolVisualization` 现在是独立的 memo 组件，稳定的复制回调不会使历史卡片随新文字重新渲染。未展开的已完成记录只生成摘要，首次展开才加载正文。展开后的 DOM 会保留；运行中的工具仍即时显示参数、输出和完成状态。存储和模型上下文里的工具结果没有裁剪。

隔离压力用例包含 40 条大型 read 工具记录，随后发送 120 个文本片段。相同本机流程中，流式窗口内的长任务由 34 次、累计约 4.56 秒降至 0 次；这只代表该压力用例，不能保证任意插件或硬件均无长任务。网络发送耗时和服务端存档耗时另计。

`test/chatStreamingPerformanceBrowser.test.mjs` 验证折叠结果不提前处理、手动展开保留、后续文本不重新清洗历史结果、草稿可输入，以及全部片段按序保留。Pi 扩展接口测试覆盖静默降级和旧提示过滤；shell 流式回归覆盖实时输出、后台运行、完成更新和续写。
