# HTML 角色卡脚本同步加速

“正在同步角色卡会话与脚本环境…”期间，HTML 等待启动脚本、会话切换事件、MVU 初始变量及一次绘制完成。本次保留这些条件，优化它们之前的下载路径。

- 运行时创建后立即为启用的 startup 脚本添加 `modulepreload`。仅预取静态 import / re-export；动态导入、禁用脚本和消息触发脚本不会被提前执行。
- 桌面服务在下载模块后预取其静态依赖图。每次图遍历最多 32 个模块、4 层；后台下载最多 4 路并发，队列最多 64 项。失败不阻断根模块，实际执行时仍可重试。
- 相同模块请求合并。原始源码缓存在应用数据目录的 `cache/tavern-modules/`，重新启动或更换本地端口后仍可复用；相对导入按本次服务地址重新改写。
- 遵守上游 `no-store` / `no-cache`、`max-age` 和 `Age`。精确版本或提交缓存最长一年；可变地址最长五分钟，无明确缓存期限时不视为新鲜。过期时使用 ETag / Last-Modified 校验；下载失败不静默替换为过期源码。
- 原 CDN 800 ms 后仍未完成下载时并行尝试已有的 cdn.jsdelivr.net 备用地址，成功后取消另一条请求；不再必须等完整的 30 秒超时才尝试备用地址。
- 缓存损坏、目录不可写时仍使用正常下载。内存最多保留 64 个源码条目，磁盘清理至 128 项，大模块不写入持久缓存。

前端预加载适用于桌面与 Android；持久模块缓存、依赖图预取和 CDN 竞速由桌面 Node 服务实现。Android 原有模块代理继续工作。

## 验证

`test/tavernStartupPerformanceBrowser.test.mjs` 使用可控的慢模块图验证：后续脚本和嵌套依赖在首个脚本等待下载期间预取，但模块求值仍按原顺序；HTML 在异步 CHAT_CHANGED 变量更新后才运行；全新浏览器上下文、重启服务并换端口后没有新增上游下载。`test/tavernModuleLoader.test.mjs` 验证缓存到期、304、来源更新、损坏缓存、写入失败、下载失败重试、慢线路取消及图遍历上限。

使用当前角色卡的隔离副本复测，不修改实际会话。相同的浏览器操作路径中，优化前同步提示显示约 1.84 秒；优化后首次下载约 1.52 秒，连续两次重启服务、重新载入原始会话并使用全新页面时，同步提示没有再出现，模块上游请求为零。首次下载受 CDN 状态影响，这组结果不代表每张卡片或每种网络的固定耗时，也不包含卡片自身远程页面和图片的加载时间。

## 显示后的自动保存卡顿

大存档的自动保存原本在界面线程中完成 `JSON.stringify` 和 fetch 请求体的编码；空闲回调仅推迟开始，无法分割这些同步工作。使用当前卡片的隔离副本加合成历史，在约 124 MB 的保存负载中记录到约 1.6 秒长任务。

超过 256 Ki 字符的大请求现在由独立 Web Worker 完成 JSON 编码和发送。界面向 Worker 分段交付数据，字符串片段最多 256 Ki 字符，每约 8 ms 让出一次执行机会。原有保存队列、会话版本校验、错误提示和等待服务器确认的行为保留。Worker 不可用或数据无法克隆时回退原 JSON 路径；请求已发出后的错误不会自动重复提交。保存使用模块加载时捕获的宿主计时器，避免角色卡脚本清理定时器时中断保存队列。

localStorage 写入前检查字符串总量；超过 8 Mi 字符的内容直接交由原有权威数据服务保存，避免先生成巨大 JSON 再因缓存配额不足失败。这个上限只影响浏览器缓存，不裁剪请求或会话。

`npm run test:save-performance` 验证分段还原、Unicode、稀疏数组、共享对象、特殊属性、Worker 故障和保存冲突，并以约 45 MB 合成历史进行浏览器验证：服务器尚未确认写入时，HTML 按钮和输入框仍可操作，界面线程没有生成巨大的 JSON，服务器最后完整保留所有 41 个会话。大存档分析复测中未再出现原先的秒级序列化/发送长任务；卡片自身脚本、布局和素材仍有独立开销。
